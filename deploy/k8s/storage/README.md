# deploy/k8s/storage — Garage S3 Object Storage on k3s (Task STO)

This directory provides the Kubernetes manifests (Kustomize) for deploying Garage S3 on `edge-1` (ADR-004, ADR-013, ADR-015, INFRASTRUCTURE §0 and §5).

## Architecture

- **StatefulSet**: `garage` (1 replica on `edge-1`, pinned version `dxflrs/garage:v1.0.1`, multi-arch `linux/amd64,linux/arm64`).
- **Storage**: Persistent Volume Claims provisioned by `local-path` on the host data volume:
  - `meta`: 1 GiB (`/var/lib/garage/meta`)
  - `data`: 70 GiB (`/var/lib/garage/data`)
- **Database Engine**: `sqlite` (stable single-file DB engine in Garage v1.0.1, low memory footprint without virtual memory ballooning).
- **Cluster Layout**: Zone `edge-1`, capacity `70G`, single node with `replication_factor = 1` for staging (ADR-013).
- **Endpoints & Networking**:
  - S3 API: `garage-s3:3900` (ClusterIP), `garage-s3-nodeport:30900` (Tailscale NodePort for `gpu-01`), and Traefik `s3.winkey.vn`.
  - S3 Web: `garage-web:3902` (ClusterIP) routed from Traefik `media.winkey.vn` / `winkey-media.winkey.vn`.
  - Admin API: Port `3903` bound strictly inside the cluster.

## Buckets & Permissions (Least Privilege)

The automated bootstrap Job (`garage-bootstrap`) provisions buckets and generates dedicated access keys with minimal privileges:

| Bucket | Purpose | Consumers & Permissions |
|---|---|---|
| `winkey-raw` | User raw video uploads (multipart, presigned) | `upload-svc` (read + write, owner for CORS)<br>`transcoder` (read only) |
| `winkey-media` | Transcoded HLS segments and static web assets | `transcoder` (read + write)<br>`video-svc` (read + write, owner for cleanup) |
| `winkey-pg-backup` | PostgreSQL daily database backups | `pg-backup` (read + write, owner) |

### Kubernetes Secrets

Generated by the bootstrap Job and stored in Kubernetes (never in git, never printed in logs):

| Secret Name | Consumed By | Keys Provided |
|---|---|---|
| `garage-key-upload-svc` | `upload-svc` | `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_ENDPOINT`, `S3_PUBLIC_ENDPOINT`, `S3_REGION`, `S3_RAW_BUCKET` |
| `garage-key-transcoder` | `transcoder-svc` & `gpu-01` | `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_ENDPOINT`, `S3_REGION`, `S3_RAW_BUCKET`, `S3_MEDIA_BUCKET` |
| `garage-key-video-svc` | `video-svc` | `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_ENDPOINT`, `S3_REGION`, `S3_MEDIA_BUCKET` |
| `garage-key-pg-backup` | `cnpg-backup` / cron | `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_ENDPOINT`, `S3_REGION`, `S3_BACKUP_BUCKET` |

## CORS & Website Configuration

### 1. `winkey-raw` (Direct Browser Presigned Uploads)
- **AllowedOrigins**: `https://winkey.vn`, `https://www.winkey.vn`
- **AllowedMethods**: `PUT`, `GET`, `HEAD`
- **AllowedHeaders**: `*`
- **ExposeHeaders**: `ETag`
- **MaxAgeSeconds**: `3600`

### 2. `winkey-media` (HLS Video Segment Streaming)
- **AllowedOrigins**: `https://winkey.vn`, `https://www.winkey.vn`
- **AllowedMethods**: `GET`, `HEAD`
- **AllowedHeaders**: `Range`
- **ExposeHeaders**: `Content-Length`, `Content-Range`, `ETag`
- **Website Hosting**: Enabled (`garage bucket website --allow winkey-media`), allowing Host `winkey-media.winkey.vn` to serve `/v/*` over HTTP to host Nginx `proxy_cache`.

## Lifecycle & Retention

During bootstrap, bucket lifecycle configuration (`AbortIncompleteMultipartUpload`) is attempted on `winkey-raw`. Note that:
- Per-object video retention (7 days after `READY`) is managed by `upload-svc` janitor (or background cron), as Garage does not implement per-object lifecycle policies (INFRASTRUCTURE §5).
- Cleanup of stale multipart uploads is handled by `upload-svc` janitor.
- Attempt rotation and deletion on `winkey-media` is handled by `video-svc` janitor.

## Provisioning via Ansible

Run from the node or admin workstation:

```bash
cd deploy/ansible
# Dry run
ansible-playbook -i inventory.yml site.yml -l edge-1 -c local --check --diff
# Apply
ansible-playbook -i inventory.yml site.yml -l edge-1 -c local
```

The Ansible role `storage_k3s`:
1. Generates `garage-rpc-secret` and `garage-admin-token` if not present in the cluster.
2. Applies manifests via `k3s kubectl apply -k deploy/k8s/storage`.
3. Waits for `statefulset/garage` rollout and `job/garage-bootstrap` completion.
4. Second run reports `changed=0` (fully idempotent).

## Transcoder Worker on `gpu-01` Setup (ADR-015)

The transcoder worker on `gpu-01` runs outside k3s as a systemd service. To configure its S3 access:

1. Extract the credentials from `garage-key-transcoder` on `edge-1`:
   ```bash
   sudo /usr/local/bin/k3s kubectl get secret garage-key-transcoder -n default -o jsonpath='{.data.S3_ACCESS_KEY_ID}' | base64 -d
   sudo /usr/local/bin/k3s kubectl get secret garage-key-transcoder -n default -o jsonpath='{.data.S3_SECRET_ACCESS_KEY}' | base64 -d
   ```
2. On `gpu-01`, update the systemd environment file (e.g. `/etc/default/winkey-transcoder` or `services/transcoder/deploy/gpu-01/transcoder.env`):
   ```ini
   S3_ENDPOINT=http://100.113.240.3:30900
   S3_REGION=garage
   S3_ACCESS_KEY_ID=<TRANSCODER_KEY_ID>
   S3_SECRET_ACCESS_KEY=<TRANSCODER_SECRET_KEY>
   S3_RAW_BUCKET=winkey-raw
   S3_MEDIA_BUCKET=winkey-media
   ```
3. Restart the service on `gpu-01`:
   ```bash
   systemctl restart winkey-transcoder
   ```

## Scaling: Upgrading to RF 2 or Cloudflare R2

- **To RF 2 (3 edge nodes)**: Garage does not support live in-place RF expansion from 1 to 2. To expand to 3 VPS:
  1. Stand up the new 3-node Garage cluster with `replication_factor = 2` on edge-1, edge-2, edge-3.
  2. Use `rclone sync` to replicate buckets from the 1-node instance to the new cluster.
  3. Update service endpoints to point to the new cluster.
- **To Cloudflare R2 / AWS S3**: Because all Winkey services use standard S3 SDKs with path-style addressing support (`libs/go/s3x`), migrating to R2 requires only setting `S3_ENDPOINT=https://<account>.r2.cloudflarestorage.com`, updating S3 keys, and changing `S3_PUBLIC_ENDPOINT`.
